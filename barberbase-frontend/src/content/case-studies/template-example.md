This file exists to prove the case-study template (frontmatter, typography, SEO tags) renders
correctly end to end. It is marked `draft: true`, so it is excluded from `/case-studies`,
`sitemap.xml`, and gets a `noindex` tag on its own page. It stays out of the public site until a
real case study replaces it.

## Structure a real case study should follow

- **Shop**: name, city, and what routing mode they run (walk-in, appointment, or both).
- **Problem**: what was happening before — described plainly, no invented figures.
- **What changed**: which locked features they use — queue joins, WhatsApp alerts, appointment
  booking, arrival PIN confirmation, staff dashboard.
- **Result**: only include a number if it comes from the shop's own reporting. Otherwise, describe
  the mechanism of what changed, not a guessed outcome.
