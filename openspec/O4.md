# UNIT: O4 — tier admin routes on openapi.yaml

REPO: barberbase-core
BRANCH: from clean main after O5 + spec backfill, clean working tree

## Context

T2 shipped the tier price resolver and tier admin CRUD as domain and
repository layers with no HTTP surface. This unit adds the eight routes.

Largest openapi unit. Patterns proven by O5 and to be reused: generated
structs (never hand-built maps), explicit path parameter names, inline types
rather than $ref where nullable or description is needed, 404 rather than
403 for cross-tenant.

## Routes — from T2's HTTP Handoff

| Method + path | Backed by |
|---|---|
| GET /v1/admin/tiers?include_inactive= | ListTiers |
| POST /v1/admin/tiers | CreateTier |
| PATCH /v1/admin/tiers/{tier_id} | UpdateTier |
| POST /v1/admin/tiers/{tier_id}/default | SetDefaultTier |
| DELETE /v1/admin/tiers/{tier_id} | DeactivateTier (soft) |
| PUT /v1/admin/staff/{staff_member_id}/tier | AssignStaffTier |
| PUT /v1/admin/tiers/{tier_id}/prices/{service_variant_id} | UpsertOverride |
| POST /v1/admin/tiers/{tier_id}/prices/bulk | BulkApplyTierPrices |

All StaffJWT, role owner/manager. tenant_id and location_id from JWT
claims, never the body (Law 11).

DELETE performs a SOFT delete (is_active=false). Hard delete is not offered
— T1 proved staff_members.tier_id and queue_entries.required_tier_id have no
ON DELETE clause, so a hard delete returns a raw 23503. Document the soft
semantics explicitly in the operation description. Consistent with O5's
DELETE /media/{id}, which also archives.

## Ninth route

| Method + path | Backed by |
|---|---|
| GET /v1/admin/tiers/{tier_id}/prices | ListResolvedPrices |

Returns the resolved matrix for one tier across all active variants at
the location. Per row: service_variant_id, variant_name, base_price_paise,
price_paise (effective), base_duration_minutes, duration_minutes
(effective), is_offered, inherited (bool).

`inherited` is load-bearing. A sparse matrix means an absent override row
and an override equal to base are indistinguishable on the wire without
it, and the admin UI needs to show "inherited from base" differently from
"explicitly set to the same value." Document that.

New repository work: lift bulk apply's existing "active variants for this
location" query into a shared method. No new resolution logic —
pricing.ResolveSelection and Resolved are reused as-is.

## Error mapping — implement exactly

| Error | Status |
|---|---|
| ErrTierNotFound | 404 |
| ErrTierInUse | 409, body names the blocking barbers |
| pricing.ErrNegativePrice | 400 |
| duplicate (location_id, name) | 409 |
| duplicate (location_id, rank) | 409 |
| cross-tenant tier or variant | 404, never 403 |

ErrTierInUse must carry the barber names in the response body — an owner
tapping "delete tier" needs to know who is blocking it, not a constraint
violation. Never surface a raw 23503.

## Bulk apply semantics — settled in T2, do not revisit

Request is `{delta_paise}` XOR `{percent}`. Both present, or neither, is 400.

- Fixed-rupee delta: exact integer arithmetic, never rounded.
- Percentage: half-up to the nearest whole rupee. x.50 rounds UP.
- No floating point at any step.
- A delta producing a negative price is refused, not clamped.
- Touches price_paise only. duration_minutes and is_offered on existing
  rows are preserved — a price adjustment must never silently re-enable a
  service a junior isn't allowed to do.

Document all of this in the operation description; an owner will call it
from a UI that says "+₹100 on all Senior" and needs to know what it does.

## Sparse matrix

UpsertOverride DELETES the row when the submitted values equal the
variant's base values, rather than storing a redundant one. Document this
— a client that PUTs base values and then GETs will not see the row, and
that is correct, not a bug. An is_offered=false row is never redundant
even at base price.

## $ref constraint — proven in both directions

O2 confirmed oapi-codegen strips nullable and sibling description beside a
$ref. O5 confirmed inlining preserves both. Tier fields that are nullable:
duration_minutes on an override (NULL = inherit), tier_id on
AssignStaffTier (null = clear), description on a tier. Inline them.

## Verify before writing

1. Every field each response declares, and whether the backing method can
   populate it at every call site. O3 and O5 both hit this — a declared
   field no producer can honestly fill is the failure mode. Report per
   field.
2. Whether PUT /v1/admin/staff/{staff_member_id}/tier collides with any
   existing staff route. Report the existing staff admin surface.
3. Whether ListTiers returns enough for an admin UI to render the price
   matrix, or whether a separate matrix-read endpoint is needed. If the
   matrix cannot be read back, the eight write routes are unusable — report
   before writing, this may be a ninth route.
4. Whether any filter or lookup ListTiers performs lacks an index. T1
   created UNIQUE(location_id, name), UNIQUE(location_id, rank) and
   idx_staff_tiers_one_default. A migration is a separate unit. This
   applies equally to ListResolvedPrices, which reads every active
   variant for a location — report a missing index the same way.
5. Whether the domain layer already refuses cross-tenant access on all
   eight methods, or whether any needs an ownership check in the handler
   as O5's ownsReferencedRow did. T2's A8 asserted this — confirm it holds
   for every method, including the two that take a second ID
   (staff_member_id, service_variant_id).

## Accept

- **A1** Spec edited, make gen-api run against a clean-tree baseline,
  tool-only regeneration. Nine new operations, no change to any existing
  operation or schema. Report the diff.
- **A2** All nine routes reachable, each returning a generated struct.
  Assert handler signatures use them, not maps.
- **A3** Every error in the mapping table returns its specified status on
  every one of the nine routes that can produce it, each triggered by a
  real condition, not a stub.
- **A4** ErrTierInUse's 409 body contains the blocking barber names.
- **A5** Law 11 on all nine routes, including both two-ID routes: a
  cross-tenant tier, staff member or variant returns 404 and mutates
  nothing. Assert the target row is unchanged afterwards.
- **A6** SetDefaultTier clears the old default in one transaction;
  concurrent calls serialise rather than violating
  idx_staff_tiers_one_default.
- **A7** UpsertOverride at base values deletes the row. Assert the row
  count, and assert an is_offered=false row at base price survives.
- **A8** Bulk apply rounding table over HTTP: 350+10%→385, 355+10%→391,
  345+10%→380, 299+10%→329, 350−₹50→300 exact, 350−10%→315, 355−10%→320.
  Verify each expected value against the stated rule before asserting it.
- **A9** Bulk apply is idempotent: a second identical call does not
  compound. Computed from base, never from the current override.
- **A10** Bulk apply preserves duration_minutes and is_offered on existing
  rows.
- **A11** Role gate: a barber gets 403 on all nine; no JWT gets 401.
- **A12** make verify-api exits 0.
- **A13** Full suite green; T2's A1–A12 pass unchanged.
- **A14** Decoded swaggerSpec carries all nine paths with correct
  security, and nothing was stripped beside a $ref.
- **A15** The resolved matrix returns one row per active variant at the
  location, including variants with no override row.
- **A16** inherited is true for a variant with no override row, false for
  one with an override — including an override whose values equal base
  but which exists because is_offered is false.
- **A17** An inactive variant does not appear.
- **A18** Tenant and location scoped; another shop's variants never appear.
- **A19** A tier with zero overrides returns every variant at base values,
  all inherited true.
