UNIT: O2 — document stale_warning: tier_unavailable

REPO: barberbase-core
BRANCH: from clean main after API1, clean working tree

CONTEXT
T3 writes stale_warning = 'tier_unavailable' on queue_entries whose
required tier has zero on-shift barbers. The column is VARCHAR(30)
with no CHECK; openapi types it as a free-form nullable string with
no enum, and it is already on the wire in QueueEntryStaff. T3
therefore needed no spec change to ship the value.

This unit documents the value so a dashboard client knows it exists.
Description-only. No new field, no new path, no enum.

WHY NO ENUM
stale_warning already carries undocumented watchdog values
('called_5min', 'called_10min', 'in_progress_overrun', and whatever
else the watchdog emits). Adding an enum would either omit those —
making the spec wrong — or require enumerating values this unit has
not audited. Keep it type: string and describe the known values in
prose. If you disagree after auditing, report before changing course.

THE CHANGE
  QueueEntryStaff.stale_warning description gains the known values,
  including tier_unavailable and what it means operationally: the
  entry requires a tier with no on-shift barber, so no one can call
  it. Audit the watchdog for every value it actually writes and list
  them all — a description that documents one value and silently
  omits four is worse than the current empty one.

VERIFY BEFORE WRITING
  1. Every literal assigned to stale_warning anywhere in the
     codebase. Quote each with its file:line and the condition that
     triggers it.
  2. Every place stale_warning is CLEARED, and under what condition.
     A reader needs to know when a warning goes away.
  3. Whether stale_warning appears on any schema other than
     QueueEntryStaff. If it is on more than one, all get the same
     description or the spec contradicts itself.
  4. Whether description sits beside a $ref anywhere on this field —
     API1 found that oapi-codegen silently drops description and
     nullable in that position. If so, the doc will not reach
     generated.go and you must report that before proceeding.
