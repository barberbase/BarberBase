CONTEXT — read this first, it is unusual
openapi.yaml has been treated as FROZEN in every unit so far. Five
units shipped fully-tested repository and domain layers with no HTTP
surface, because adding one would have required editing it. This unit
is the exception: it exists to unfreeze the file, add the missing
surface, and regenerate.

That inversion matters. In every other unit, editing openapi.yaml is
an automatic FAIL. Here it is the job. But the frozen-file discipline
still applies to 001_complete_schema.sql, migrations/*.sql, and to
generated.go as a hand-edited file — generated.go changes ONLY by
running the generator, never by hand.

THE CHANGE
  LocationStatus gains:
    next_open_at:
      type: string
      format: date-time
      nullable: true
      description: >
        Instant the shop next opens, RFC3339 with the location's UTC
        offset (e.g. 2026-08-29T10:00:00+05:30). null when no open
        day exists within eight days. Present whether the shop is
        open or closed; when open it is the next opening, not the
        current one.
  NOT added to required.

  Then wire it. B3 computes NextOpenAt *time.Time on
  repository.ShopStatusResult and both resolvers return it; the

    GetLocationStatus (handlers_public.go:762) — keep the result,
      add the field to the response.
    ResolveBookingOptions (:1038) and CreateCheckinIntent (:1198)
      discard the result and likely need nothing — confirm.
